# 기획 초안 비교 실험

2026-09-16. 실제 고객 인터뷰가 아닌 합성 입력을 사용한 제품 검증입니다. 영상 제작 워크플로우와 독립된 서비스 사례입니다.

## 무엇을 확인했나

가상 신규 예능의 소개 콘텐츠를 준비하는 상황으로 세 가지 입력을 구성했습니다.

| 상황 | 기대 | 오프라인 결과 |
| --- | --- | --- |
| 짧은 메모 한 개 | 없는 예산·지표를 만들어 채우지 않기 | 입력 내용만 남기고 미작성 항목 표시 |
| 30초 세로 / 3분 가로 제안 | 상반된 제작 방향을 검토 대상으로 노출 | 수정 전 검토 표시 없음 → 수정 후 사람 검토 표시 |
| 2명·3일 → 1명·1일로 조건 변경 | 변경된 조건에 맞는 안을 판단 | 로컬 규칙은 의미 판단을 하지 못함. 실제 LLM 검증 필요 |

입력과 결과는 `baseline/`, 수정 후 결과는 `offline/`에 있습니다. JSON은 원문·선택 전후·검증 항목을, Markdown은 내보낸 문서를 담습니다.

`live/`는 빌드된 로컬 서버에 실제 HTTP 요청을 보낸 기록입니다. 세 응답 모두 `source: local_harness`로 돌아왔습니다. API 경로와 대체 동작은 확인했지만, OpenAI 모델의 의미 비교는 아직 검증하지 못했습니다. 모델 호출이 아닌 결과를 성공으로 집계하지 않도록 실행 스크립트는 이 경우 실패 종료합니다.

## 발견한 문제와 개선

구조 검증 통과가 사용 가능한 기획안이라는 뜻은 아니었습니다. 로컬 대체 경로가 첫 의견을 임시 선택하면서 검토 표시를 생략했습니다. 모든 로컬 임시 선택을 사람 검토 대상으로 변경했습니다. 의미 기반 충돌 탐지까지 해결했다고 주장하지 않습니다.

선택 변경 후 원본과 관련 없는 문서 항목이 유지되고, 입력 초안의 발췌문이 보존되는 것을 확인했습니다. 이는 함수 수준의 시나리오 검증이며 브라우저 전체 사용성 검증은 아닙니다.

## 다음 실험

OpenAI 연결 후 동일 입력으로 `--live`를 실행합니다. 응답 출처가 `openai`인지 먼저 확인하고, 포맷·타깃·제작 범위 충돌과 변경된 제약 조건의 반영 여부를 사람이 판정합니다. HTTP 200이나 JSON 유효성만으로 성공으로 판정하지 않습니다.

현재 12개 항목은 서비스 기획에 맞춰져 있어 영상 기획에서 불필요한 항목이 많습니다. 콘텐츠용 구성(목적, 시청자, 메시지, 형식, 소재, 일정, 미결정 사항)은 별도 개선 대상입니다. 아직 범용 콘텐츠 기획서 완성 도구로 소개하지 않습니다.
